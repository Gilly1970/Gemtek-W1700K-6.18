Changes made to Dan's patches while rebasing - please review
-------------------------------------------------------------
1/3 dt-bindings: mainline already has "firmware" (not "binary"), the Block
    Ack region and firmware-name, so the patch now only adds "dma". Same
    oneOf structure as the OpenWrt version. Commit message rewritten.
    Note: the WLAN branch keeps minItems: 4, so a 2- or 3-entry list
    (firmware, pkt[, tx-pkt]) that today's binding accepts would now be
    rejected. No in-tree DTS uses that (mainline en7581.dtsi has no NPU
    node), but reviewers may ask. A WLAN board must also list "ba" to add
    "dma" (by design). The example still shows the 5-region list.
    Checked: dt_binding_check clean; validated firmware / firmware+dma /
    5 WLAN / 5 WLAN+dma / 4 WLAN = valid, firmware+pkt / dma-without-ba /
    dma-first = rejected.

3/3 mailbox: code is v6 as posted, rebased. Two changes: the per-core
    dmam_alloc_coherent() loop now sits after the pool is attached (patch
    2) and before airoha_npu_run_firmware(); the in-code comment no longer
    says "0.0 despite MBOX success" but gives the window/swiotlb reason.
    Commit message rewritten around the address window (answers Kuba's
    v6 "masks the underlying problem" question). No Fixes: tag - add
    6f884eb87a79 and target net instead if you prefer.
